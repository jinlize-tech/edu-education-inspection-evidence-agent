# JLZ-EDU-AG-021 Codex执行任务书

## 1. 基线

- 任务编号：`JLZ-EDU-EXPANSION-30-FULL-DELIVERY`
- 候选来源：`CAND-010`
- 正式产品：`JLZ-EDU-AG-021` / 年检与专项检查证据包
- 类型：Agent
- 批次：1
- 业务中心：09 合规与风险中心
- 版本基线：`EDUCATION_BASELINE_V1.0.0`
- 产品版本：`1.0.0`
- 许可证：Apache-2.0

## 2. 用户、痛点与目标

- 用户：校长、行政主管、合规负责人、财务/教务协作人员
- 痛点：年检、专项检查或主管部门抽查来临时，证据散落在不同部门，常见问题是找不到、版本不一致或责任不明。
- 目标：按检查主题建立证据目录，逐项核验制度、记录、资质、合同、财务与整改闭环，编排补证任务。

## 3. 输入契约

| 键 | 名称 | 类型 | 必填 |
|---|---|---|---|
| `inspection_notice` | 检查通知或要求 | string | 是 |
| `campus_scope` | 检查校区范围 | array | 是 |
| `evidence_inventory` | 现有证据材料清单 | array | 是 |
| `responsible_roles` | 责任角色 | array | 是 |
| `deadline` | 提交截止日期 | string | 是 |

## 4. 工作流

1. 解析检查要求
2. 建立证据树
3. 盘点现有材料
4. 核验版本与签批
5. 生成补证任务
6. 进行抽样模拟
7. 形成提交包索引

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点检查通知/要求、校区信息、现有制度与记录、资质、合同、财务与教务样本、材料责任人、截止日期，标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕按检查主题建立证据目录，逐项核验制度、记录、资质、合同、财务与整改闭环，编排补证任务。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按解析检查要求 → 建立证据树 → 盘点现有材料 → 核验版本与签批 → 生成补证任务 → 进行抽样模拟 → 形成提交包索引设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由校区负责人/材料责任部门复核真实材料、原件、签批、责任人与对外提交版本。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `检查证据目录`
- `材料索引`
- `缺口表`

## 7. 差异化与排重

- 与现有产品：标准化产品负责体系和日常检查；本产品专门面向外部检查，以证据完整性和提交包为目标。
- 排重检查：部分重叠；现有产品提供检查方法，本产品组织外部检查证据链与提交材料。
- 独立理由：无需完整标准化项目也可独立完成一次检查准备。

## 8. 安全与人工门禁

- 复核角色：校区负责人/材料责任部门
- 复核范围：真实材料、原件、签批、责任人与对外提交版本
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
